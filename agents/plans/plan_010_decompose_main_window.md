## 1. 🎯 Цель и контекст
- **Проблема / Задача:** `MainWindow` (`src/gui/main_window.py`) — God-object: **74 метода, 1215 строк**. Он одновременно отвечает за настройки, drag&drop, конвертацию, превью, пресеты, i18n, статистику текста, поиск, историю экспорта, ревизии, AI-инструменты и голосовой ввод. Следствие — расползание багов: правка в одной зоне ломает другую (именно так в TASK-003 нашлись затёнённые дубли миксина, а в TASK-008 — недостижимые заглушки). Файл `dialogs.py` (1534 строки) и `main_window.py` (1282) держат **33% всего кода** проекта.
- **Ожидаемый результат:** `MainWindow` — тонкий оркестратор (жизненный цикл, сборка UI, связи сигналов). Тематические группы методов вынесены в миксины **по уже существующему в проекте паттерну** (`ToolMethodsMixin` в `window_tools.py`). Поведение **не меняется** — это перенос кода, а не рефакторинг логики.

### Принципиальное ограничение (важно)
- **Язык/стек не меняем.** Проблема — структурная, не языковая. Переписывание на Rust/C#/C++ воспроизвело бы тот же God-object плюс потеряло бы рендереры (WeasyPrint/Office/OCR/TTS). Декомпозиция решает именно причину.
- **Никаких изменений поведения.** Только перемещение тел методов и (при необходимости) списка базовых классов.

## 4. 🛡️ Риски, сайд-эффекты и план отката
- **Риск: «тихая» потеря метода** при переносе (как уже было с откатом `ui_layout.py` в TASK-008). Митигация: после каждого этапа — тест, сверяющий полный список методов `MainWindow` (MRO) с эталонным списком из 74 имён; прогон тестов на каждом шаге.
- **Риск: MRO.** Митиксация: у миксинов нет `__init__`/`super()`; конфликтов имён быть не должно (проверяется тестом на дубликаты имён методов между миксинами).
- **Риск: побочные импорты.** Митиксация: `grep` перед удалением каждого импорта; ленивые импорты внутри методов переносятся «как есть».
- **План отката:** `git revert` — перенос изолирован по этапам (отдельный коммит на группу), каждый коммит самостоятельно откатывается.
