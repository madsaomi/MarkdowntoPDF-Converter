# 🐛 Баг: резервный TOML-парсер не читал многострочные массивы (красный CI на Python 3.10)

**Дата:** 2026-10-21  
**Статус:** ✅ FIXED  
**Затронутые модули:** `tests/test_dependency_sync.py` (`_load_pyproject`)

---

## Симптом → Причина

- **Симптом:** CI-job `Tests` падал **только** на Python 3.10 (шаг
  «Run tests», `test_dependency_sync.py`), тогда как 3.11–3.14 были зелёными.
- **Причина:** `_load_pyproject()` использует `tomllib` (есть только в 3.11+).
  Для 3.10 задуман резервный построчный парсер, но он не понимал
  **многострочные массивы**:

  ```toml
  dependencies = [
      "markdown>=3.5",
      ...
  ]
  ```

  Регулярка `^(\w+)\s*=\s*\[(.*)\]?$` захватывала строку `dependencies = [`,
  но элементы лежат на **следующих** строках и проверялись условием
  `line.startswith("dependencies")` — которое для них ложно. Итог:
  `project["dependencies"] == []` → `test_pyproject_parses` падал на
  `assert "markdown" in {...}`.

- **Как обнаружено:** локально установлен настоящий PyQt6 (Python 3.15) для
  воспроизведения CI; затем CI-прогон показал 4/5 зелёных и падение на 3.10.
  Симуляция `tomllib = None` воспроизвела ошибку на любом интерпретаторе.

## Исправление

Переписан резервный парсер: отслеживает вход в массив (`key = [`) и
накапливает строковые элементы до закрывающей `]`, поддерживая как
`[project] dependencies`, так и `[project.optional-dependencies]` extras.
Вынесен помощник `_collect_array_items()`.

Добавлен регрессионный тест `test_pyproject_fallback_parser_py310`, который
форсирует `tomllib = None` и проверяет разбор многострочных массивов.

## Проверка
- `tomllib = None` → базовые зависимости (`markdown`, `pypdf`) и extras
  (`gui`, `docx`) читаются корректно; `test_dependency_sync.py` зелёный.
- Батарея 29/29.

## Уроки
- Ветка, выполняющаяся только на одной версии Python (здесь — 3.10-fallback),
  практически не покрыта тестами → нужен явный тест с её форсированием.
- CI-матрица по версиям окупается: баг был невидим локально (3.15) и на 3.11+.
