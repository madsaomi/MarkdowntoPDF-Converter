# 🐛 Баг: неочищенный колонтитул → CSS-инъекция в итоговый документ

**Дата:** 2026-10-21  
**Статус:** ✅ FIXED  
**Затронутые модули:** `src/core/renderer.py` (`PDFRenderer.render_html`)

---

## Симптом → Причина

- **Симптом:** текст нижнего колонтитула (footer) вставлялся в шаблон
  **без очистки**, хотя рядом в коде вычислялся очищенный вариант. В итоговый
  HTML попадал блок:

  ```css
  @bottom-center {
      content: "<пользовательский текст>";
  }
  ```

  Пользовательский текст, содержащий кавычку, **вырывался из CSS-строки** и
  мог добавить произвольные CSS-правила в документ.

- **Причина:** в `render_html` санитизация применялась только к водяному знаку:

  ```python
  safe_watermark = ''.join(c for c in (watermark or '') if c in safe_chars)
  safe_footer   = ''.join(c for c in (resolved_footer or '') if c in safe_chars)
  ...
  self.template.render(
      watermark=safe_watermark,
      footer_text=resolved_footer,   # ← BUG: нужен был safe_footer
      ...
  )
  ```

  `safe_footer` вычислялся, но **не использовался** — в шаблон уходил
  `resolved_footer`. Значение `safe_chars` (whitelist) не содержит `"`, `{`,
  `}` и управляющих символов, поэтому очищенный текст безопасен.

- **Как обнаружено:** при написании тестов на `render_html` (PLAN-013, рост
  покрытия) проверка «в колонтитуле не осталось управляющих символов»
  упала. Проверка с PoC подтвердила инъекцию:

  ```
  payload: X"; } body { background-image: url("http://evil/x.png"); } .z { content: "
  результат (до фикса):
      content: "X"; } body { background-image: url("http://evil/x.png"); } .z { content: "";
  ```

  Водяной знак при этом очищался корректно — расхождение подсказало, что
  именно `footer_text` передаётся неочищенным.

## Исправление

```python
-            footer_text=resolved_footer,
+            footer_text=safe_footer,
```

Одно слово. Публичные интерфейсы и поведение не изменились: колонтитул по-прежнему
отображается, просто из него вырезаются символы, ломающие CSS.

## Проверка

- После фикса payload остаётся **внутри** строки `content: "..."` и не создаёт
  новых CSS-правил; управляющие символы (`\x00`, `\x07`) вырезаны.
- Добавлены регрессионные тесты:
  - `test_render_html_sanitizes_watermark_and_footer` — колонтитул и водяной
    знак очищаются от управляющих символов;
  - `test_render_html_footer_cannot_break_out_of_css` — колонтитул не может
    закрыть CSS-строку и создать новое правило.

## Уроки

- Тесты на «управляющие символы» поймали баг, который не ловился глазами:
  внешне документ выглядел корректно.
