# 🐛 Баг: смешанные inline- и блочные формулы ломали HTML-превью LaTeX

**Дата:** 2026-10-22  
**Статус:** ✅ FIXED  
**Затронутые модули:** `src/core/latex_preview.py` (`render_latex_in_html`)

---

## Симптом → Причина

- **Симптом:** если в тексте встречались и inline-формула `$…$`, и блочная
  `$$…$$`, результат замены формул на картинки был испорчен — второй тег
  `<img>` вставлялся **внутрь атрибута** первого:

  ```html
  A $x$ B <img src="URL(y^2)" alt="y^2" style="vertical-align<img
  src="URL(x)" alt="x" style="vertical-align: middle;" />iddle;" /> C
  ```

  В браузере/`QTextBrowser` такая разметка отображается мусором, формула
  теряется. Текст только с inline- или только с блочными формулами работал
  корректно — поэтому баг легко было не заметить.

- **Причина:** `find_latex_expressions` собирает результаты в два прохода:
  сначала **все блочные** `$$…$$`, затем **все inline** `$…$`. Порядок в
  списке получается не по позиции в тексте:

  ```python
  find_latex_expressions("A $x$ B $$y^2$$ C")
  # [(8, 15, 'y^2'), (2, 5, 'x')]   ← не отсортировано
  ```

  `render_latex_in_html` же применяет замены с накоплением смещения
  (`offset += len(img_tag) - (end - start)`), то есть **требует** обхода
  слева направо. На второй итерации смещение считалось от правой формулы,
  а применялось к левой — замена попадала в уже вставленный тег.

- **Как обнаружено:** тест `test_render_latex_in_html_replaces_all_formulas`
  (PLAN-013) на строке `"A $x$ B $$y^2$$ C"`.

## Исправление

```python
     result = text
     offset = 0
-    for start, end, formula in expressions:
+    # BUG_013: find_latex_expressions отдаёт сначала все блочные формулы, затем
+    # инлайновые, поэтому смещения нельзя применять в исходном порядке —
+    # замены должны идти слева направо.
+    for start, end, formula in sorted(expressions, key=lambda e: e[0]):
```

Сортировка сделана **внутри потребителя**, а не в `find_latex_expressions`:
публичный порядок возврата не меняется (его использует `show_latex_preview`,
где порядок косметический), а инвариант «замены слева направо» становится
локальным и очевидным.

## Правило предотвращения

- **Если алгоритм накапливает смещение при заменах, входной список обязан
  быть упорядочен по позиции** — либо сортировка внутри, либо явный assert
  на монотонность. «Порядок как пришёл» здесь неявный контракт, который
  легко нарушить, поменяв реализацию поиска.
- **Тест на несколько замен должен содержать разные типы элементов**
  (inline + block): однотипные случаи не выявляют перестановку.
- **Сравнивать результат целиком, а не «содержит `<img`»** — при порче
  разметки подстрочные проверки проходят.
